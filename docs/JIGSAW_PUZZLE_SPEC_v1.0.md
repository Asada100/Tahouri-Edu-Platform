# Tahouri — Jigsaw Puzzle Specification v1.0

## هدف

یک Puzzle واقعی تصویری که دانش‌آموز با جابه‌جایی قطعات، تصویر کامل را می‌سازد.

## تجربه بازیکن

```text
تصویر ناقص و به‌هم‌ریخته
        ↓
مشاهده قطعات
        ↓
انتخاب / گرفتن قطعه
        ↓
جابه‌جایی یا تعویض جای قطعات
        ↓
تشخیص پیشرفت
        ↓
کامل شدن تصویر
```

## اصل طراحی

- قطعه باید واقعاً قابل جابه‌جایی باشد.
- محل مناسب باید برای کاربر قابل درک باشد.
- حرکت باید با انیمیشن کوتاه و طبیعی همراه شود.
- بازخورد نباید مزاحم حل Puzzle شود.
- تصویر بخشی از مسئله است، نه تزئین صفحه.
- Puzzle نباید به فرم «انتخاب پاسخ» تبدیل شود.

## داده

نمونه قرارداد:

```js
{
    type: "jigsaw",
    objective: "تصویر را کامل کن",
    instruction: "قطعه‌ها را جابه‌جا کن تا تصویر کامل شود.",
    difficulty: 1,
    content: {
        image: "assets/images/puzzles/example.jpg",
        rows: 2,
        cols: 2
    },
    interaction: {
        mode: "swap"
    },
    feedback: {
        correct: "قطعه درست قرار گرفت",
        complete: "تصویر کامل شد"
    },
    hints: [],
    scoring: {},
    progression: {}
}
```

## مدل منطقی

هر قطعه دارای:
- `id`
- `correctIndex`
- `currentIndex`

برد زمانی حل شده است که برای تمام قطعات:

```text
currentIndex === correctIndex
```

## حرکت

در نسخه اول، تعامل منطقی `swap` است:

```text
piece A ←→ piece B
```

این انتخاب عمداً از Drag پیچیده‌تر شروع نمی‌شود؛ Drag/Touch مستقیم در لایه UI پیاده می‌شود و منطق هسته مستقل می‌ماند.

## سختی

نسل اول:

- Level 1: 2×2
- Level 2: 3×3
- Level 3: 4×4
- Level 4: 4×4 با تصویر پیچیده‌تر
- Level 5: 5×5 و سرنخ کمتر

در آینده سختی فقط با افزایش تعداد قطعات تعیین نمی‌شود و می‌تواند از شکل قطعات، شباهت بخش‌های تصویر، محدودیت حرکت و راهنمایی مرحله‌ای استفاده کند.

## آموزش

Jigsaw به‌خودی‌خود محتوای آموزشی نیست؛ ارزش آموزشی آن از محتوای تصویر و هدف فعالیت می‌آید.

بنابراین تصویر می‌تواند:
- شکل‌های هندسی باشد.
- بخش‌های یک آزمایش علمی باشد.
- مراحل یک فرایند باشد.
- تصویر آموزشی فارسی باشد.
- نقشه یا نمودار آموزشی باشد.

## محدودیت

Jigsaw نباید به PuzzleEngine فعلی تحمیل شود تا زمانی که قرارداد State و lifecycle آن مشخص و تست شود. هسته فعلی مستقل است و بعداً از مسیر رسمی Activity Platform متصل خواهد شد.
