تاریخ بررسی: 2026-10-19  
مخزن: `Asada100/Tahouri-Edu-Platform`  
شاخه: `master`

## خلاصه اجرایی

- موتور Pattern موجود است و به PuzzleTypeRegistry متصل شده است.
- موتور Spatial موجود است و در حال حاضر modeهای `legacy`، `place` و `symmetry` را پشتیبانی می‌کند.
- مسیر کلی اجرای Puzzle از PuzzleEngine به `activityReady` و سپس PuzzleScreen برقرار است.
- Coordinate Plane و Point Symmetry در کد بررسی‌شده به‌عنوان mode پیاده‌سازی‌شده تأیید نشدند؛ در سند Spatial نسخه 1.2 برنامه‌ریزی شده‌اند.
- تست اختصاصی Pattern/Spatial پیش از این ممیزی در پوشه `tests` پیدا نشد. تست رگرسیون و Workflow مستقل به مخزن افزوده شدند.
- Workflow در اجرای اولیه یک نقص در fixture تست داشت؛ اصلاح شد و اجرای بعدی در GitHub Actions با موفقیت پایان یافت.
- در این مرحله منطق اجرایی موتورهای Pattern و Spatial تغییر نکرده است.

## یافته‌های قطعی و ریسک‌ها

### یافته‌های قطعی

1. Activity فعلی Pattern تنها یک الگوی نمونه ساده دارد؛ وجود handler به معنی پوشش آموزشی متنوع نیست.
2. Activity فعلی Spatial Place فقط سه شکل در Grid سه‌درسه دارد؛ برای اثبات پوشش همه سناریوهای Place کافی نیست.
3. Activity فعلی Symmetry از مولد تصادفی و difficulty برابر medium استفاده می‌کند؛ تنظیم محور روی random است.
4. Handler تقارن محور را با انعکاس خانه‌ها روی Grid محاسبه می‌کند؛ این منطق معادل تقارن نقطه‌ای یا صفحه مختصات عددی نیست.
5. تست‌های اختصاصی Pattern/Spatial پیش از این تغییر در فهرست تست‌ها وجود نداشتند.
6. فایل وضعیت قدیمی Puzzle (نسخه 2.0، تاریخ 2026-08-21) Pattern و Spatial را به‌صورت کامل ثبت نمی‌کند؛ بنابراین نباید به‌عنوان وضعیت جاری این دو handler استفاده شود.

### ریسک‌های نیازمند پوشش بیشتر

1. نقص شناسه تکراری قطعه در Place/Symmetry شناسایی و اصلاح شد: Spatial اکنون پیش از شروع، ID تکراری را رد می‌کند؛ این رفتار در تست رگرسیون پوشش داده شده است.
2. اعتبارسنجی فعلی عمدتاً ساختار اولیه و محدوده هدف را بررسی می‌کند؛ آزمون داده‌های مرزی و ناقص باید توسعه یابد.
3. تعامل واقعی Drag/Drop روی موبایل، اندازه‌های مختلف صفحه، چرخش دستگاه و Pointer خارج از محدوده، با تست واحد اثبات نمی‌شود و همچنان به تست واقعی نیاز دارد.
4. سطح دشواری مولد باید با کتاب و هدف آموزشی پایه تطبیق داده شود؛ صرف تفاوت تعداد خانه‌ها تضمین‌کننده دشواری آموزشی مناسب نیست.
5. Pattern از برابری مقدار برای بررسی پاسخ استفاده می‌کند؛ آزمون مقادیر عددی، رشته‌ای و داده‌های غیرمجاز باید حفظ شود.

## تست و CI افزوده‌شده

- تست: `tests/pattern-spatial-regression.test.js`
- Workflow: `.github/workflows/pattern-spatial-regression.yml`
- پوشش فعلی:
  - ثبت handlerهای Pattern و Spatial
  - شروع و اعتبارسنجی Pattern
  - پاسخ درست/غلط Pattern برای داده عددی و رشته‌ای
  - شروع Place، placement صحیح، جابه‌جایی و بازگرداندن قطعه
  - رد Grid نامعتبر، هدف تکراری و ورودی نامعتبر
  - رد ID تکراری قطعه
  - جلوگیری از بررسی Spatial پیش از حرکت
  - تولید تقارن افقی/عمودی و بررسی رابطه بازتاب و محدوده خانه‌ها

اجرای نخست به دلیل ناقص بودن fixture تست شکست خورد؛ fixture اصلاح شد. سپس نقص ID تکراری به‌صورت تست‌محور پوشش داده و در Handler اصلاح شد. اجرای نهایی GitHub Actions موفق بود:
https://github.com/Asada100/Tahouri-Edu-Platform/actions/runs/39303450322

این نتیجه فقط تست‌های نوشته‌شده را تأیید می‌کند و به معنی تأیید کامل UX یا همه حالت‌های موتور نیست.

## مراحل اجرایی بعدی

1. افزودن آزمون داده‌های نامعتبر: ID تکراری، Grid نامعتبر، قطعه ناقص، هدف تکراری و ورودی خارج از Grid.
2. افزودن آزمون تعویض دو قطعه و جابه‌جایی قطعه از محل قبلی.
3. افزودن آزمون Pattern برای داده عددی، رشته‌ای، گزینه خالی و مقادیر مرزی.
4. افزودن آزمون integration از PuzzleEngine تا state و check؛ با حفظ قرارداد lifecycle موجود.
5. ممیزی کامل eventهای pointer در PuzzleScreen و تطبیق با رفتار موبایل.
6. بررسی CSS مربوط به Grid، محور تقارن، target ghost و ناحیه لمس.
7. تطبیق محتوای واقعی پایه ششم با اهداف کتاب، پیش از ساخت Activity آموزشی جدید.
8. طراحی قرارداد داده برای Coordinate Plane، مستقل از Grid خانه‌ای.
9. طراحی و آزمون فرمول‌های تقارن نقطه‌ای حول مبدأ و مرکز دلخواه، پس از تثبیت قرارداد مختصات.
10. فقط پس از موفقیت آزمون‌های قبلی، پیاده‌سازی قابلیت‌ها به‌صورت تغییرهای کوچک و مستقل.
11. 3D و Projection در این مرحله اولویت ندارند.
