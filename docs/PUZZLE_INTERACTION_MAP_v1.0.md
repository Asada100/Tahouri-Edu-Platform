# Tahouri Edu Platform — Puzzle Interaction Map v1.0

## هدف

این سند مشخص می‌کند هر خانواده Puzzle نسل جدید چگونه باید با کاربر تعامل داشته باشد. هدف این نیست که همه Puzzleها یک حرکت مشترک داشته باشند؛ هدف این است که حرکت از ماهیت خود Puzzle بیاید.

## اصل تصمیم

```text
ماهیت چالش
   ↓
کاری که بازیکن باید انجام دهد
   ↓
Interaction مناسب
   ↓
Feedback متناسب با همان حرکت
```

اگر برای حل Puzzle فقط «وارد کردن جواب» لازم باشد، ابتدا باید بررسی شود که آیا واقعاً Puzzle طراحی کرده‌ایم یا یک فرم.

## نقشه تعامل

| Puzzle | هدف بازیکن | تعامل اصلی | بازخورد طبیعی |
|---|---|---|---|
| Jigsaw | کامل کردن تصویر | swap / drag | snap + progress |
| Sudoku | قرار دادن رقم درست با استدلال | tap / select / place | selected + conflict |
| Maze | رساندن مهره به مقصد | trace / drag | path + target |
| Nonogram | کشف تصویر با سرنخ‌ها | tap / select | selected + progress |
| Logic Puzzle | حذف گزینه‌ها و رسیدن به نتیجه | tap / select | selected + contradiction |
| Pattern / Shape | ساختن الگوی درست | drag / rotate / place | snap + target |
| Spot the Difference | پیدا کردن تفاوت‌ها | tap | selected + progress |
| Sentence Builder | ساخت جمله درست | drag / swap | snap + progress |
| Visual Math | حل مسئله با دستکاری عناصر تصویری | drag / tap / place | target + progress |
| Interactive Problem | حل مرحله‌ای یک مسئله | tap / place / build | progress + hint |

## 1. Jigsaw

بازیکن قطعات تصویر را می‌بیند و باید جای درست آن‌ها را پیدا کند.

- Interaction: `swap` در منطق، `drag`/touch در UI
- انتخاب قطعه باید حس گرفتن قطعه واقعی داشته باشد.
- محل مقصد باید واضح باشد.
- با قرارگیری درست، قطعه snap شود.
- تصویر کامل شدن را خودش نشان دهد.

## 2. Sudoku

بازیکن باید با استفاده از محدودیت‌های ردیف، ستون و ناحیه تصمیم بگیرد چه رقمی می‌تواند قرار گیرد.

- Interaction: `tap` → انتخاب خانه → `select` رقم
- ورود آزاد عدد با کیبورد تعامل اصلی نیست.
- خطای واضح باید به تعارض مربوط باشد، نه فقط «غلط است».
- سختی از اندازه، تعداد سرنخ و پیچیدگی استنتاج افزایش می‌یابد.

## 3. Maze

بازیکن باید مسیر رسیدن از شروع به مقصد را پیدا کند.

- Interaction: `trace` یا `drag`
- مسیر طی‌شده باید بلافاصله دیده شود.
- برخورد با دیوار یا مسیر اشتباه بازخورد فوری می‌دهد.
- پایان مسیر با رسیدن واقعی به مقصد مشخص می‌شود.

## 4. Nonogram

بازیکن با سرنخ‌های عددی خانه‌هایی را که باید پر یا خالی باشند کشف می‌کند تا تصویر شکل بگیرد.

- Interaction: `tap`
- یک لمس برای پر کردن و حالت دوم برای علامت‌گذاری خانه خالی.
- پیشرفت تصویری بخشی از بازخورد است.
- سرنخ‌ها منطق Puzzle هستند، نه متن توضیحی تزئینی.

## 5. Logic Puzzle

بازیکن باید از چند سرنخ رابطه درست بین گزینه‌ها را کشف کند.

- Interaction: `tap` / `select`
- انتخاب‌ها باید روی خود جدول یا عناصر Puzzle انجام شوند.
- سیستم باید امکان نشان دادن تعارض را داشته باشد.
- هدف، کشف رابطه است؛ نه تایپ پاسخ نهایی.

## 6. Pattern / Shape

بازیکن باید قطعات یا شکل‌ها را طوری بچیند یا بچرخاند که الگوی موردنظر کامل شود.

- Interaction: `drag` + `rotate` + `place`
- مقصدهای معتبر باید قابل مشاهده باشند.
- درست قرار گرفتن قطعه باید با snap مشخص شود.
- سختی از شباهت قطعات، تعداد قطعات و روابط پنهان افزایش می‌یابد.

## 7. Spot the Difference

بازیکن باید تفاوت‌های موجود در دو تصویر را پیدا کند.

- Interaction: `tap`
- انتخاب روی خود تصویر انجام می‌شود.
- ناحیه انتخاب‌شده باید علامت‌گذاری شود.
- با هر کشف، تعداد تفاوت‌های باقی‌مانده تغییر می‌کند.

## 8. Sentence Builder

بازیکن کلمات را برای ساخت جمله درست مرتب می‌کند.

- Interaction: `drag` / `swap`
- کلمه باید واقعاً جابه‌جا شود.
- جایگاه احتمالی باید برای کاربر قابل درک باشد.
- جمله کامل‌شده نتیجه طبیعی Puzzle است.

## 9. Visual Math

بازیکن باید مفهوم ریاضی را با عناصر دیداری و تعاملی حل کند؛ مثلاً گروه‌بندی، مقایسه یا ساخت مقدار.

- Interaction بسته به مسئله: `drag` / `tap` / `place`
- عدد صرفاً در یک input وارد نمی‌شود مگر اینکه خود مسئله به آن نیاز داشته باشد.
- حرکت عناصر باید بخشی از استدلال ریاضی باشد.

## 10. Interactive Problem

مسئله به چند مرحله کوچک تقسیم می‌شود و بازیکن در هر مرحله تصمیم می‌گیرد چه کاری انجام دهد.

- Interaction: `tap` / `place` / `build`
- هر مرحله باید نتیجه قابل مشاهده داشته باشد.
- Hint می‌تواند روش فکر کردن را هدایت کند، نه اینکه فوراً پاسخ را بدهد.

## سختی مشترک

سطح 1 تا 5 در همه خانواده‌ها یک معنی عددی صرف ندارد. هر خانواده باید سختی مخصوص خود را داشته باشد.

```text
Level 1 → آشنایی با منطق Puzzle
Level 2 → تصمیم‌گیری ساده
Level 3 → چند محدودیت یا مرحله
Level 4 → روابط پنهان‌تر / فضای جست‌وجوی بیشتر
Level 5 → چند استدلال پشت سر هم / کمک کمتر
```

## قانون UX مشترک

1. بازیکن باید بداند چه کاری باید انجام دهد.
2. عمل اصلی باید روی خود Puzzle انجام شود.
3. نتیجه عمل باید قابل مشاهده باشد.
4. Feedback باید نزدیک به همان عمل باشد.
5. اشتباه نباید صرفاً با پیام «غلط» نمایش داده شود اگر دلیل قابل توضیح وجود دارد.
6. Undo و Reset در Puzzleهایی که مناسب هستند باید در دسترس باشند.
7. حرکت و انیمیشن باید کوتاه و هدفمند باشند، نه تزئینی.
8. Puzzle نباید با inputهای متنی یا عددی غیرضروری به فرم تبدیل شود.

## وضعیت معماری

این سند فقط قرارداد طراحی است. در این مرحله هیچ Puzzle جدیدی به UI یا ActivityManager متصل نمی‌شود.

بعد از تثبیت این نقشه، اولین پیاده‌سازی UI برای Jigsaw انجام می‌شود و از مسیر واقعی Activity Platform تست خواهد شد.
